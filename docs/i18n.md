# Internationalisation

English is the first language of about 5% of the world. Until v0.13.0 this
framework produced English on every path a user sees — validation messages, the
generated authentication flows, the admin panel, the ops dashboard — and an
application could not change any of it without forking the templates.

## Three lines

```go
//go:embed locales/*.json
var locales embed.FS

catalogue := i18n.NewWithFramework(language.English)
catalogue.Load(locales, "locales/*.json")
app.HTTP.Router.Use(catalogue.Middleware)
```

`NewWithFramework` starts from the framework's own messages, so validation, the
admin panel and the ops dashboard work in English immediately and in your
language as soon as you translate them.

`tjo make auth` already registers the middleware in generated projects.

## The catalogue

One JSON file per locale, named for its language tag. `sv.json`, `pt-BR.json`.

```json
{
  "login.title": "Logga in",
  "cart.items": {
    "one": "{count} vara",
    "other": "{count} varor"
  }
}
```

JSON because every translation tool reads it, it diffs sanely in review, and
parsing it needs nothing outside the standard library.

The format is the decision that outlives the code: it is what translators are
handed, what a translation management system imports, and the thing nobody
migrates twice.

### Placeholders are not templates

`{name}` is substituted from the arguments. It is deliberately **not**
`text/template`. A catalogue is edited by translators, frequently through a web
tool, and a format that can execute is a format in which a translation can do
something other than translate. Template syntax in a message stays literal text.

### Plurals

English has two forms, and `if count == 1` is right in English and wrong in most
of the world. CLDR defines six categories and languages use different subsets:

| Language | Categories |
|---|---|
| Japanese, Chinese | other |
| English, Swedish | one, other |
| Polish, Russian | one, few, many, other |
| Arabic | zero, one, two, few, many, other |

So a plural message is an object keyed by category, and you fill in only the
ones your language uses. Everything falls back to `other`, which every language
has.

```go
p := i18n.From(ctx)
p.N("cart.items", 3)              // "3 varor"
p.N("cart.items", 1)              // "1 vara"
```

A design that stored `{singular, plural}` would be broken for Polish before it
shipped, and would be found by a Polish user rather than by a test.

## In a handler

```go
func (h *Handlers) Checkout(w http.ResponseWriter, r *http.Request) {
    p := i18n.From(r.Context())

    h.App.HTTP.Session.Put(r.Context(), "flash", p.T("cart.checked_out"))
}
```

`From` never returns nil. A context with no printer — a background job, a test,
a handler mounted outside the middleware — gets one for the fallback locale, so
translating is never a nil check.

## In a Jet template

```jet
<h2>{{ t("login.title") }}</h2>
<p>{{ n("cart.items", count, "count", count) }}</p>
<html lang="{{ lang }}" dir="{{ dir }}">
```

`TemplateData` also carries `.Lang` and `.Dir`.

## Negotiation

Most explicit first:

1. `?lang=sv` — so a link can carry a language, and choosing one sets a cookie
2. the `lang` cookie
3. `Accept-Language`
4. the catalogue's fallback

A user's stated preference beats their browser's, because a browser configured
once in a hotel in 2019 is not a preference.

Matching is `language.Matcher`, not string comparison: `sv-FI` selects `sv`, and
`pt-BR` reaches `pt` before falling to English.

The response carries `Content-Language` and `Vary: Accept-Language`. Without the
second, a shared cache serves one visitor's language to everyone — the bug that
makes a site randomly Swedish.

Override it for signed-in users:

```go
catalogue.MiddlewareWithOptions(i18n.Options{
    From: func(r *http.Request) language.Tag {
        if tag := session.GetString(r.Context(), "locale"); tag != "" {
            return language.Make(tag)
        }
        return language.Und // fall through to the default order
    },
})
```

## Right to left

Arabic, Hebrew, Persian and Urdu are four hundred million people, and a layout
that does not mirror is not merely untranslated — it is unusable.

The locale carries its direction. Put it on the document:

```jet
<html lang="{{ lang }}" dir="{{ dir }}">
```

Then use **logical** CSS properties rather than physical ones:
`margin-inline-start` rather than `margin-left`, `text-align: start` rather than
`left`. In Tailwind: `ps-4` and `me-2` rather than `pl-4` and `mr-2`. The admin
panel and the generated skeleton both do this, and the admin panel has a test
that fails if a physical property comes back.

## Adding a language

```bash
tjo make locale sv
```

It walks the project for the keys actually in use and writes
`locales/sv.json` with them, empty. It merges on re-run, so adding a screen and
running it again adds the new keys and keeps the translations.

Keys are left empty rather than pre-filled with English: a translator seeing
`""` knows it is untranslated, and an empty value falls back to the source
language at runtime anyway.

Keys must be literals. A key built from a variable cannot be found by any tool,
and a generator that pretended otherwise would produce a catalogue that is
quietly incomplete.

## Formatting

```go
p.Number(1234.5)          // 1 234,5 in Swedish, 1,234.5 in English
p.Money("SEK", 199)       // the currency's own decimal places
p.Date(t)                 // 2026-08-06, 06/08/2026 or 08/06/2026
p.DateTime(t)
p.Percent(0.15)
```

Yen has no minor unit and Kuwaiti dinar has three. `Money` uses the currency's,
not a guess, because getting it wrong is a rounding error in somebody's invoice.

## What the framework ships

Only English. A framework that shipped a stale Turkish translation would be
worse than one that shipped none, because the stale one silently wins over the
source language. Translations of the framework's own 120 keys are welcome as
contributions.
